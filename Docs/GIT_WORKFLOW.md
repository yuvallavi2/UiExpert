# Git Workflow - UiExpert Project

## Overview

This document defines the Git workflow and best practices for the UiExpert project, which is a hybrid Magic XPA and Angular application.

## Branch Strategy

### Main Branches

- **`main`** (or `master`) - Production-ready code
  - Always stable and deployable
  - Protected branch - requires pull request reviews
  - Only merge thoroughly tested features

- **`develop`** - Integration branch for features
  - Default branch for development work
  - Contains latest development changes
  - Features are merged here first before going to main

### Supporting Branches

#### Feature Branches
- **Naming**: `feature/<short-description>` or `feature/<issue-number>-<description>`
- **Purpose**: Develop new features or enhancements
- **Branch from**: `develop`
- **Merge back to**: `develop`
- **Examples**:
  - `feature/event-registration`
  - `feature/123-member-search`
  - `feature/ui-dark-mode`

#### Bugfix Branches
- **Naming**: `bugfix/<short-description>` or `bugfix/<issue-number>-<description>`
- **Purpose**: Fix bugs found in develop branch
- **Branch from**: `develop`
- **Merge back to**: `develop`
- **Examples**:
  - `bugfix/event-date-validation`
  - `bugfix/456-login-error`

#### Hotfix Branches
- **Naming**: `hotfix/<version>-<description>` or `hotfix/<critical-issue>`
- **Purpose**: Critical fixes for production
- **Branch from**: `main`
- **Merge back to**: `main` AND `develop`
- **Examples**:
  - `hotfix/1.0.1-security-patch`
  - `hotfix/critical-data-loss`

#### Release Branches
- **Naming**: `release/<version>`
- **Purpose**: Prepare for production release
- **Branch from**: `develop`
- **Merge back to**: `main` AND `develop`
- **Examples**:
  - `release/1.0.0`
  - `release/2.1.0`

#### Magic XPA Metadata Updates
- **Naming**: `magic/<short-description>`
- **Purpose**: Updates from Magic XPA Studio (XML metadata changes)
- **Branch from**: `develop`
- **Merge back to**: `develop`
- **Examples**:
  - `magic/add-event-program`
  - `magic/update-member-datasource`

## Workflow Process

### 1. Starting New Work

```bash
# Update your local develop branch
git checkout develop
git pull origin develop

# Create a new feature branch
git checkout -b feature/your-feature-name
```

### 2. Making Changes

```bash
# Make your changes to the code
# Stage changes
git add <files>

# Commit with a descriptive message (see commit guidelines below)
git commit -m "feat: add event registration form"

# Push to remote
git push origin feature/your-feature-name
```

### 3. Keeping Branch Updated

```bash
# Regularly sync with develop to avoid conflicts
git checkout develop
git pull origin develop
git checkout feature/your-feature-name
git merge develop

# Or use rebase (if you prefer linear history)
git rebase develop
```

### 4. Creating Pull Request

1. Push your branch to remote
2. Create pull request from your branch to `develop`
3. Fill in PR description with:
   - What changed
   - Why it changed
   - How to test
   - Screenshots (for UI changes)
4. Request reviews
5. Address feedback
6. Merge when approved

### 5. After Merge

```bash
# Delete local branch
git branch -d feature/your-feature-name

# Delete remote branch
git push origin --delete feature/your-feature-name

# Update develop
git checkout develop
git pull origin develop
```

## Special Considerations for Magic XPA

### Magic XPA Files (Source/ directory)

- **NEVER manually edit XML files in Source/ directory**
- All changes must come from Magic XPA Studio
- Create `magic/*` branches for metadata updates
- Always regenerate Angular components after Magic metadata changes

### Workflow for Magic XPA Changes

1. Make changes in Magic XPA Studio
2. Create branch: `git checkout -b magic/your-change`
3. Commit Magic XPA generated XML files
4. Regenerate Angular components (if needed)
5. Commit generated Angular code separately
6. Create PR with clear description of Magic changes

### Handling Generated Files

**Auto-generated files to commit:**
- `magic-metadata/**/*.json` - Component metadata
- `src/app/magic/**/*.g.ts` - Generated components
- `src/app/magic/component-list.g.ts` - Component registry
- `src/app/magic/magic.gen.lib.module.ts` - Module config

**Files to review but commit:**
- `Source/*.xml` - Magic XPA metadata (generated by Magic Studio)

## Protected Files

The following files should be carefully reviewed before committing:

- `Source/**/*.xml` - Should only change via Magic XPA Studio
- Configuration files with sensitive data
- Database files (should be in .gitignore)

## Collaboration Guidelines

### Code Review

- All code must be reviewed before merging to develop
- Reviewers should check:
  - Code quality and standards
  - No manual edits to generated files
  - Proper separation of Magic and Angular code
  - Tests pass (if applicable)

### Conflict Resolution

- Prefer rebasing for clean history on feature branches
- Use merge commits when merging to develop/main
- For Magic XPA conflicts - resolve in Magic Studio, not in XML

### Communication

- Keep PR descriptions detailed
- Link to related issues/tasks
- Update TODO.md for significant changes
- Document breaking changes clearly

## Git Commands Cheat Sheet

```bash
# Create and switch to new branch
git checkout -b feature/my-feature

# View current status
git status

# Stage all changes
git add .

# Commit with message
git commit -m "feat: your message here"

# Push to remote
git push origin feature/my-feature

# Pull latest from develop
git checkout develop && git pull

# Merge develop into your branch
git checkout feature/my-feature
git merge develop

# View commit history
git log --oneline --graph

# Undo last commit (keep changes)
git reset --soft HEAD~1

# Discard all local changes
git reset --hard HEAD
```

## Troubleshooting

### Accidentally committed to wrong branch
```bash
git reset --soft HEAD~1  # Undo commit, keep changes
git stash               # Stash changes
git checkout correct-branch
git stash pop          # Apply changes
```

### Need to update commit message
```bash
git commit --amend -m "new message"
```

### Merge conflicts
```bash
# After conflicts occur
git status              # See conflicting files
# Edit files to resolve conflicts
git add <resolved-files>
git commit
```
