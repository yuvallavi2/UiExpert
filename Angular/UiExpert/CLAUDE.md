# CLAUDE.md

This file provides guidance to Claude Code when working with the Angular UiExpert application.

## Project Overview

This is an Angular 19 application that integrates with Magic XPA, a low-code platform. The application uses Magic XPA's code generation capabilities to create Angular components from metadata JSON files.

## Application Startup Flow

When you run `npm start` and navigate to `http://localhost:4200/`, the following sequence occurs:

### 1. Bootstrap Sequence
1. **Browser loads** [src/index.html](src/index.html) containing `<app-root></app-root>`
2. **Angular initializes** via [src/main.ts](src/main.ts) which bootstraps [AppModule](src/app/app.module.ts)
3. **AppModule loads**:
   - `MagicModule` - Core Magic XPA framework
   - `MagicGenLibModule` - All auto-generated components (10 components)
   - `MagicRoutingModule` - Route configuration
   - Registers `LazyLoaderService` for dynamic component loading

### 2. Magic Framework Takeover
1. **AppComponent renders** with template: `<magic-root></magic-root>` - Magic takes control from here
2. **Component Registry** ([component-list.g.ts](src/app/magic/component-list.g.ts)) registers all Magic components in a hash map:
   ```typescript
   magicGenCmpsHash = {
     StartProgram_StartProgram: StartProgram_StartProgram,
     Welcome_Welcome: Welcome_Welcome,
     EventCard_EventCard: EventCard_EventCard,
     // ... 7 more components
   }
   ```

### 3. Backend Connection & Component Execution
1. **Magic connects** to backend server (configured in [public/assets/server-config.json](public/assets/server-config.json)):
   - Server: `http://IL-Ylavi.MSE.Corp/MagicScripts412/MGrqispi.dll`
   - AppName: `UiExpert`
2. **Magic XPA server determines** which component to load first (typically `StartProgram`)
3. **StartProgram component** ([src/app/magic/mainWC/StartProgram/StartProgram.component.ts](src/app/magic/mainWC/StartProgram/StartProgram.component.ts)) executes:
   - Extends `TaskBaseMagicComponent`
   - Initializes form controls via `MgFormControlsAccessor`
   - Communicates with Magic XPA backend for business logic
   - Renders UI in the browser

### 4. Dynamic Component Loading
- All routes use `RouterContainerMagicComponent` (see [app.routes.ts](src/app/app.routes.ts))
- When navigating (e.g., `/MList`, `/EventCard`), Magic's `LazyLoaderService` dynamically loads the corresponding component
- The actual component is determined by the Magic XPA server based on the route name

**Key Point**: Angular provides the framework, but **Magic XPA controls which components load and when**. The starting program and navigation flow are defined in the Magic XPA backend, not in Angular code.

## Critical Rules

**BEFORE STARTING ANY WORK - READ AND ACKNOWLEDGE:**

1. **DO NOT edit generated files** - Files with `.g.ts` suffix or auto-generated components will be overwritten
2. **DO NOT modify files in magic-metadata/** - These are generated by Magic XPA
3. **ONLY modify** - Custom TypeScript, HTML, and CSS files 

Files to NEVER edit:
- `*.g.ts` - Generated TypeScript files
- `src/app/magic/component-list.g.ts` - Component registry
- `src/app/magic/magic.gen.lib.module.ts` - Generated module
- `src/app/magic/**/*.component.ts` - Auto-generated components
- `magic-metadata/**/*.json` - Magic XPA metadata

## Magic XPA Integration

### How It Works

1. **Magic XPA Backend** generates metadata JSON files
2. **Magic CLI** (`@magic-xpa/cli`) reads metadata and generates Angular components
3. **Generated components** extend `TaskBaseMagicComponent`
4. **Component registry** (`component-list.g.ts`) maps component names to classes
5. **Lazy loader** dynamically loads components at runtime

### Server Configuration

Backend connection configured in:
- Development: `magic-metadata/server-config.json`
- Runtime: `public/assets/server-config.json`

Current configuration:
```json
{
  "protocol": "HTTP",
  "server": "IL-Ylavi.MSE.Corp",
  "requester": "MagicScripts412/MGrqispi.dll",
  "appName": "UiExpert"
}
```

### Component Naming Convention

Magic components use the format: `{Folder}_{ComponentName}_{ComponentName}`

Examples:
- `EventCard_EventCard` - Event card component
- `MList_MList` - Member list component
- `StartProgram_StartProgram` - Start program component

### Generated File Structure

Each Magic component has:
- **Metadata**: `magic-metadata/{Feature}/{Component}/{Component}.json`
- **Component**: `src/app/magic/{Feature}/{Component}/{Component}.component.ts`
- **Template**: `src/app/magic/{Feature}/{Component}/{Component}.component.html`
- **Controls**: `src/app/magic/{Feature}/{Component}/{Component}.mg.controls.g.ts`

## Common Development Workflows

### Adding Custom Logic to Generated Components

Since you cannot edit generated components directly, use Angular's composition patterns:

1. **Wrapper Component Pattern**:
```typescript
// Create a wrapper component
@Component({
  selector: 'app-event-card-wrapper',
  template: '<app-event-card [data]="data" (event)="handleEvent($event)"></app-event-card>'
})
export class EventCardWrapperComponent {
  handleEvent(event: any) {
    // Add custom logic here
  }
}
```

2. **Service-based Extension**:
```typescript
// Create a service for custom business logic
@Injectable({ providedIn: 'root' })
export class EventService {
  customEventLogic() {
    // Add custom logic here
  }
}
```

### Styling Approaches

1. **Global Styles**: [src/styles.css](src/styles.css) - Application-wide styles
2. **Tailwind Utilities**: Use Tailwind classes in templates
3. **Custom CSS**: Create separate stylesheets for custom components

DO NOT add styles to generated component files.

### Working with Forms

All forms use Angular Reactive Forms:
- Access controls via `mgfc` (MgFormControlsAccessor) in generated components
- Control names defined in `MgControlName` enum
- Form validation defined in metadata

### Regenerating Components from Magic Metadata

When Magic XPA metadata changes:

1. Magic XPA Studio exports updated metadata
2. Magic CLI regenerates component files
3. Files automatically updated:
   - `src/app/magic/**/*.component.ts`
   - `src/app/magic/component-list.g.ts`
   - `src/app/magic/magic.gen.lib.module.ts`
4. Test in development server: `npm start`

## Debugging & Troubleshooting

### Common Issues

1. **Component not found**:
   - Check `component-list.g.ts` registry
   - Verify metadata exists in `magic-metadata/`
   - Regenerate components if needed

2. **Build errors after metadata update**:
   - Clean build: `rm -rf .angular dist`
   - Reinstall dependencies: `npm install`
   - Rebuild: `ng build`

3. **Server connection issues**:
   - Verify `public/assets/server-config.json`
   - Check network connectivity to Magic XPA server
   - Review browser console for CORS errors
